## Phase 5A-1 최종 화면 검수 보완

2026-10-19 후속 검수. 위 최초 검증 기록은 보존하고, 최종 결과는 아래 기록을 우선한다.

### 공정 선택과 금액의 의미

1. `estimate-state.js`의 대분류 선택값은 계산 활성화 조건이다. 예를 들어 가구 철거는
   `sectionDemolitionEnabled && demolitionFurnitureEnabled`일 때 계산한다. 선택 해제는 입력값 삭제가 아니다.
2. `loadEstimateIntoUi()`는 저장된 customerQuote/internalSummary/internalDetails가 있으면 저장 결과를 복원한다.
   입력만으로 불러오기 직후 자동 재산정하거나 과거 견적을 새 가격으로 덮어쓰지 않는다.
3. 입력을 실제 변경하면 기존 전체 재계산 경로를 사용한다. 입력이 baseline과 다시 같아지면
   `syncLoadedEstimateSnapshot()`은 저장 스냅샷으로 되돌아간다. 배관 청소 전용 후처리 예외도 변경하지 않았다.
4. 목록 금액은 화면에서 사용하는 `customerQuote.groups[].total`을 9개 표시 공정으로 묶어 읽는다.
   체크 해제된 공정의 저장 금액을 임의로 0원 처리하거나 참고금액으로 바꾸지 않는다.
5. 상단 총액과 고객 출력도 같은 표시 스냅샷을 사용한다. 원가·이익을 화면에 새로 가져오지 않는다.

검수에 사용한 `latestEstimate()`는 철거 입력만 저장하면서 다른 공정의 금액도 담은 합성 fixture다.
8개 유상 그룹과 필름 0원 행을 9개 공정에 표시한 합계는 3,770,000원이다.
입력 자체를 현재 엔진으로 계산한 값 130,000원과 저장 고객 견적 3,770,000원은 서로 다르다.
이는 이번 UI가 새로 계산한 오류가 아니라 fixture 입력/저장 결과의 불일치와 기존 저장값 보존 정책의 조합이다.
운영 견적을 조회하여 동일 문제가 있다고 확정한 것은 아니다.

| 합성 견적 상태 | 목록 합계·상단·고객 출력 | 표시 출처 |
|---|---:|---|
| 저장 견적 불러오기 | 3,770,000원 | 저장 견적 |
| 철거 선택 해제 후 계산 | 0원 | 현재 입력 계산 |
| 철거 재선택으로 원래 baseline 복귀 | 3,770,000원 | 원래 저장 견적 복원 |

위 결과를 admin/manager/staff에서 검증했다. Staff 변경 검증에는 실제 `calculateStaffEstimate()`와
`projectStaffEstimate()`를 사용하고, DB I/O만 합성 fixture로 대체했다.
새 견적의 9개 공정 각각 선택·해제 및 복수 선택에서는 현재 계산값·목록 합계·상단·고객 출력이 모두 같았다.
원가/고객가/저장 산식은 변경하지 않았다. 기존 복원 정책을 바꾸려면 별도 승인과 업무정책 결정이 필요하다.
